# ZEB-ROI 아키텍처 · 큰 틀

> **최종 방향**: AI Agent 기반 ZEB / 그린리모델링 평가 및 ROI 산정
> 최종 갱신: 2026-07 · 상태: 방향 확정, 단계적 구현 중

## 0. 한 줄 정의

> **BIM 한 번 입력으로 ZEB 인증 등급과 그린리모델링 사업 경제성을 동시에 산출하는 AI Agent 플랫폼.**
> 계산·판정은 결정론적 엔진과 물리 시뮬레이션이, 언어와 오케스트레이션만 LLM이 담당한다.

## 1. 설계 원칙 (타협 금지)

| # | 원칙 | 이유 |
|---|------|------|
| **P1** | **파인튜닝 대신 Agent + RAG** | 단가·법령·보조율이 수시로 바뀐다. 파인튜닝은 학습 시점에 지식이 고정돼 stale해지고, 재학습 비용이 크며, 갱신 이력을 추적할 수 없다. |
| **P2** | **계산은 절대 LLM에게 시키지 않는다** | LLM의 역할은 ① 자연어 → 파라미터 추출 ② 도구 호출(오케스트레이션) ③ 결과 → 자연어 설명. **숫자는 전부 엔진이 만든다.** |
| **P3** | **법령은 RAG로 원문 인용, 없으면 없다고 답한다** | 법령 환각은 실무에 치명적. 검색된 조항 밖의 내용은 생성하지 않고 출처(파일·페이지)를 함께 제시한다. (실무 담당자 피드백으로 검증) |
| **P4** | **ZEB와 그린리모델링은 판정 로직을 분리하되, 데이터·해석 기반은 공유한다** | 법적으로 다른 제도라 판정은 분리해야 한다. 그러나 같은 건물을 두 번 파싱하면 숫자가 어긋난다. **공유 코어 위에 두 트랙**을 얹는다. |

## 3. 두 트랙 분리 (P4)

같은 건물, 다른 제도. **판정은 분리, 기반은 공유.**

| | **Track A · ZEB 인증** | **Track B · 그린리모델링 사업** |
|---|---|---|
| 목표 | 인증 등급 취득 | 사업 선정 + 경제성 확보 |
| 근거 | ZEB 인증기준 고시 (제1·2·3호) | GR 가이드라인 종합형 정량평가표 |
| 판정 | 자립률 **또는** 1차에너지소요량, **그리고** BEMS → +등급~5등급 | 100점 (기술요소 80 + 사업여건 20) → A+~D |
| 핵심 수치 | 에너지자립률, 1차에너지소요량(×2.75) | 보강 우선순위, Max Cost, 보조금, 자부담 |
| 담당 | ZEB 팀 | 그린리모델링 팀 |
| **공유 코어** | **BIM 파싱 · 에너지 해석 · 단가DB · 법령 RAG — 하나만 존재** | |

> ⚠️ **팀을 2개로 나누되, 공유 코어의 인터페이스(공통 건물모델 스키마 + 해석 결과 스키마)를 먼저 합의하고 나눌 것.**
> 인터페이스 합의 없이 병렬로 가면 같은 건물에서 두 팀의 숫자가 어긋난다.

## 5. 에너지 해석 업그레이드 (가장 중요한 과제)

### 현재 (간이 추정)
```python
# core/zeb_evaluator.py
BASE_ENERGY_BY_USE = {"어린이집": 200, ...}   # 용도별 원단위 kWh/㎡·년
GR_ENERGY_REDUCTION = {"3_외벽단열보강": 0.15, ...}  # 요소별 절감률(가정치)
```
- 장점: 빠르고 의존성 없음, 무료 티어에서 동작
- 한계: **"왜 15%인가?"에 답할 근거가 약함.** 건물 형상·기후·향·창면적비가 반영되지 않음

### 목표 (물리 기반 시뮬레이션)
```
Revit → gbXML → OpenStudio(SDK) → IDF → eppy(파라미터 조작) → EnergyPlus 실행
     → 연간 소요량·절감량(kWh) → ZEB 자립률/등급 → ROI
```
- **eppy는 IDF 편집·실행 래퍼이지 지오메트리 생성기가 아니다.** 형상은 gbXML/OpenStudio가 만든다.
- EnergyPlus 실행 파일이 필요 → **Streamlit 무료 티어(1GB)에서 실행 불가.**
  → **해석은 로컬/배치로 돌리고 결과를 캐시**하는 구조로 간다. (웹은 결과 조회·시나리오 비교만)
- 검증 지표로 **CVRMSE ≤ 15%** (실측 대비) 도입 검토 — UBEM 표준 관행

### 얻는 것
ROI가 **가정치 절감률**이 아니라 **시뮬레이션 절감량(kWh)** 을 먹게 되면 체인 전체의 신뢰도가 완성된다:
> BIM 형상 → 물리 시뮬 → 절감량 → ZEB 등급 → 경제성

## 6. BIM 입력 경로 — 공부항목 ①에 대한 결론

> **질문: "revit 파일을 웹서버에 넣고 분석이 되는지? rvt으로 해석하면 메리트가 클 것 같음"**

**결론: `.rvt`를 웹서버에서 직접 파싱하는 것은 사실상 불가능하다.** `.rvt`는 Autodesk 독점 바이너리 포맷이고 공개 파서가 없다. 서버에서 열려면 Revit이 설치된 Windows가 필요하다.

현실적인 3가지 경로:

| 경로 | 방법 | 장점 | 단점 | 추천 용도 |
|---|---|---|---|---|
| **A. APS(구 Forge)** | `.rvt` 업로드 → Model Derivative API로 IFC/속성 변환 | **.rvt 그대로 업로드 가능** | 클라우드 의존·계정 필요, 변환 대기 | "rvt 그대로"가 꼭 필요할 때 |
| **B. IFC** | Revit에서 IFC export → `ifcopenshell`(Python) | 개방 표준, 무료, 벤더 종속 없음, 물량 추출 강함 | export 1회 수동 | **물량·객체 분석** |
| **C. gbXML** ⭐ | Revit에서 gbXML export → OpenStudio/EnergyPlus | **애초에 에너지 해석용 포맷**, Revit 기본 지원 | 형상 단순화 이슈 | **에너지 해석** |
| D. Dynamo JSON | 현재 방식 | 이미 동작 | Revit+Dynamo 수동 단계 | fallback 유지 |

**권장**: **에너지 해석 = gbXML**, **물량·객체 = IFC**, **JSON은 fallback으로 유지.**
"rvt를 웹에 올려서 바로"는 APS를 붙이면 가능하지만, 졸업설계 스코프에서는 gbXML/IFC가 훨씬 저렴하고 확실하다.
(디자인빌더에서 파일이 깨진 문제도 gbXML 경로로 우회 가능성이 높다 — 형상을 다시 그리지 않고 export 설정만 조정)

## 6-B. 법령 근거 (팀 학습문서 v4 반영)

> 출처: 팀 내부 학습문서 v4 (성제건 1398) · 검증 케이스 도담어린이집

### 두 트랙의 법적 구조
| | Track A · ZEB | Track B · GR |
|---|---|---|
| 근거법 | **녹색건축물 조성 지원법 제17조** | **녹색건축물 조성 지원법 제27조** |
| 하위 규정 | ZEB 인증기준 고시(제2024-893호) 제4조·별표1·1의2·2 | GR 지원사업 운영 고시(제2023-385호) |
| 평가 | 자립률·1차에너지소요량 → **절대 성능** 등급 | 성능개선비율(전후 대비 **20% 이상**) → **상대 개선율** |
| 등급 | +등급~5등급 | **등급 없음** — 지원 자격 판단 |
| 편익 | 취득세 감면, 용적률·높이 완화, **수수료 환불** | 이자 보조(민간) / 사업비 직접 지원(공공) |
| **배타적 아님** | 한 건물이 GR로 성능 개선 → 그 결과가 ZEB 등급에 도달 가능. **두 트랙 대상 여부를 독립 판정한다.** | |

### 확정 규칙 (엔진에 반영 가능)
- **자립률 정식** = 순생산량 ÷ **총소요량**, `총소요량 = 1차에너지소요량 + 순생산량` (별표1)
  - 보정계수(대지 외 생산): 자립률 10%미만 0.7 / 10~15% 0.8 / 15~20% 0.9 / 20%↑ 1.0
- **인증등급 = 제1호(자립률) 또는 제2호(1차에너지소요량) 중 higher grade**, 단 **제3호 BEMS 13항목** 필수
- **ZEB 의무 대상** = 공공소유 + 공사범위(신축·재축·전부개축·**별동증축**) + 연면적 → 1,000㎡↑ 4등급 / 미만 5등급
  - **도담 = 단순 리모델링 → 의무 아님, 자율(임의) 신청**
- **취득세 감면** = **신축·증축·개축분만.** 3등급↑ 20% / 4등급 18% / 5등급 15%. 3년 내 인증취소 시 추징. 기한 2026.12.31
  - **재산세 감면은 2018년 종료 — 현행 아님**
- **용적률·높이 완화** = +·1등급 15% / 2등급 14% / 3등급 13% / 4등급 12% / 5등급 11% (에너지절약설계기준 별표9)
  - 완화용 자립률은 **대지 내 순생산량만** 반영 (별표1 주4)
- **수수료** = 비주거 1천~3천㎡ **390만원**(부가세 별도, 별표4) / **환불**: +~3등급 100%, 4등급 50%, 5등급 30% — **의무 대상이 아닌 자율 인증에만**
- **GR 지원 자격** = 성능개선비율 **20% 이상** + 대상공사 7종 중 1건 이상 포함
- **GR 사업 구분** = 공공기관 소유 → **공공지원사업**(사업비 직접 지원) / 민간 → 민간이자지원사업(이자 보조)
  - **도담 = 한국전력기술㈜(공공기관운영법 §4) → 공공지원사업, 보조율 50%**
- **2026 공공 GR 2.0** = 종합형 400만원/3.3㎡, 최대 70억(서울·중앙·공공 50억), 사용승인 10년↑(2016.1.1 이전)
- **평가 실내온도** = 냉방 26℃ / 난방 20℃ (별표3)
- **태양광 ≠ 태양열** — GR 고시 제7조 제6호 가목(태양광·전력)/나목(태양열·급탕). **자립률 기여 방식이 다르므로 BIM 파싱 단계에서 분리**

### 시뮬레이션 도구 (중요)
| 용도 | 도구 |
|---|---|
| **ZEB 자립률 공식 산정** | **ECO2** (에너지공단 무료 배포, ISO 13790 월간 계산) — 공식 확정은 인증기관 |
| **GR 성능개선비율** | 지정 프로그램: ECO2, ECO2-OD, GR-E, Energy Studio, **EnergyPlus**, IES-VE |

→ **EnergyPlus는 GR 지정 프로그램에 포함**되므로 eppy 방향은 제도적으로도 정당하다.
단, **ZEB 자립률의 공식 산정은 ECO2**이므로 두 도구를 트랙별로 나눠 쓴다.

## 6-C. 도담 4등급 근거 확정 (2026-07 엔진 재현 검증)

**쟁점**: 학습문서 v4는 "앱의 23.4% → 4등급 표기는 5등급으로 바로잡아야 하고, 4등급엔 태양광 증설이 필수"라고 정정 요구.

**검증 결과 — 앱의 4등급이 규정상 맞다.** 문서의 정정은 **제1호만** 본 것이다.

```
보강 후 (11개 GR 전체 적용 + BEMS 가정)
  총소요량(gross) 66.0 · 순생산량 15.43 · net 1차E소요량 50.57
  제1호 자립률 23.4%  → 5등급   (40% 미달)
  제2호 net 50.57     → 4등급   (비주거 90 미만 충족)   ←★
  최종 = 별표2 주2 "제1호 또는 제2호 중 상위" → ZEB 4등급 · 인증가능
```

**추가 검증 — PV는 4등급의 필수 조건이 아니다.**
```
PV = 0 으로 두고(태양열 오분류 정정 가정) 전체 보강 시
  자립률 0% → 제1호 미달 / net 66.0 → 제2호 4등급 → 최종 4등급 (인증가능)
  임계: 절감률 > 55% 이면 PV 없이도 제2호 4등급
```
→ **4등급은 태양광이 아니라 "효율개선으로 소요량을 90 미만으로 낮추는 것"에서 나온다.**
문서의 "PV 증설 필수"는 자립률(제1호) 경로를 전제한 결론이다.

### ⚠️ 그래도 고쳐야 하는 것 — 우리 '설명'이 틀렸다
결론(4등급)은 맞지만 **근거 서술이 사실과 다르다.**
- 앱·발표는 *"자립률 9.3% → 23.4%가 되어 4등급"* 이라고 설명해 왔다 → **오류**.
  실제 4등급은 **제2호(소요량 50.57 < 90)** 근거이고, 자립률 23.4%는 **5등급**밖에 안 된다.
- 게다가 자립률 9.3%/23.4% 자체가 **태양열 27㎡를 PV 5.4kW로 오분류**해 만든 값이다.
  실제 PV는 0개 → 참값 자립률은 0%에 가깝다(태양열은 급탕 기여).
→ **등급 결론은 유지하되, 화면·발표의 근거 문구를 제2호 기준으로 정정하고 자립률 수치는 태양열 분리 후 재산출한다.**

### 🔴 진짜 리스크 — 절감률 67%가 가정치다
제2호 4등급의 임계는 **절감률 55%**인데, 우리 값 67%는 `GR_ENERGY_REDUCTION`(요소별 절감률 **가정치**)의 합이다.
여유가 **12%p뿐**이라 ECO2/EnergyPlus로 재계산하면 **등급이 뒤집힐 수 있다.**
→ 에너지 해석 물리화(P3)가 등급 신뢰도의 전제 조건임이 수치로 확인됨.
